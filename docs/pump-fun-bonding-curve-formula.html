The pump.fun bonding curve formula, explained (with Rust code)

Every pump.fun coin starts on a bonding curve: a program-owned account that sells tokens for SOL at a price set by a formula, until the curve sells out and the coin migrates to a pool. The formula is a plain constant product, but getting a quote that matches the chain to the lamport needs the program's exact rounding. Here it is, with Rust you can run.

The curve is x · y = k over virtual reserves

The bonding-curve account stores two virtual reserves: tokens (virtual_token_reserves) and SOL (virtual_sol_reserves). Their product stays constant across a trade, like a Uniswap v2 pool. "Virtual" because a new coin starts with 30 SOL on the SOL side that nobody deposited: it only sets the starting price.

So k = 1,073,000,000 × 30 = 32,190,000,000 in whole units. The spot price is virtual_sol / virtual_tokens, about 0.000000028 SOL per token at launch. Buying removes tokens and adds SOL, so the price rises along the curve. When the 793.1 million real tokens are gone, the curve is complete and the coin migrates.

The other ~206.9 million tokens never trade on the curve: 279.9 million virtual tokens remain at the end, which is where the end price comes from (see how to calculate price and market cap).

The three trades

With vT and vS the virtual reserves in raw units (tokens × 106, lamports), and all divisions rounded down unless noted:

  • Sell t tokens: sol = floor(t × vS / (vT + t)), then each fee is taken off.
  • Buy exactly t tokens (the buy instruction): sol = floor(t × vS / (vT − t)) + 1, then each fee is added on top. The +1 makes the rounding favour the curve.
  • Spend B lamports, fees included: first the part that reaches the curve, net = floor(B × 10000 / (10000 + fee_bps)), trimmed if net plus its rounded-up fees exceeds B; then tokens = floor((net − 1) × vT / (vS + net − 1)).
  • Fees: protocol and creator fees are each ceil(sol × bps / 10000), charged separately. Coins without a creator pay no creator fee. The rates are set by pump.fun and change over time: read them from pump.fun's fee config or public docs rather than hard-coding them. 95 + 30 bps below was the published bonding-curve rate in November 2026.

Sources: the formulas follow pump.fun's published IDL and SDK. The sell and spend-SOL versions were checked against nine real mainnet trade events, fees included; see the README.

The formula in Rust, by hand

Use u128 for intermediates: t × vS overflows u64 easily.

/// Each fee is rounded up, separately: `ceil(sol * bps / 10_000)`.
fn fee(sol: u128, bps: u128) -> u128 {
    let n = sol * bps;
    n / 10_000 + u128::from(n % 10_000 != 0)
}

/// Sell `tokens`: SOL out of the constant product, rounded down, then both fees taken off.
fn sell(v_tokens: u128, v_sol: u128, tokens: u128, protocol_bps: u128, creator_bps: u128) -> u128 {
    let sol = tokens * v_sol / (v_tokens + tokens);
    sol - fee(sol, protocol_bps) - fee(sol, creator_bps)
}

/// Buy exactly `tokens`: SOL into the constant product, rounded down plus one lamport, then both fees on top.
fn buy_exact_tokens(v_tokens: u128, v_sol: u128, tokens: u128, protocol_bps: u128, creator_bps: u128) -> u128 {
    let sol = tokens * v_sol / (v_tokens - tokens) + 1;
    sol + fee(sol, protocol_bps) + fee(sol, creator_bps)
}

/// Spend `budget` lamports, fees included: how many tokens come back.
fn buy_with_sol(v_tokens: u128, v_sol: u128, budget: u128, protocol_bps: u128, creator_bps: u128) -> u128 {
    let mut net = budget * 10_000 / (10_000 + protocol_bps + creator_bps);
    let total = net + fee(net, protocol_bps) + fee(net, creator_bps);
    if total > budget {
        net -= total - budget; // rounding the fees up can overshoot by a lamport or two
    }
    (net - 1) * v_tokens / (v_sol + net - 1)
}

Checked against a real curve

This main decodes a real bonding-curve account captured from mainnet, runs the hand-written formulas and the crate side by side, and asserts they agree. It is examples/bonding_curve_formula.rs in the repository and runs in CI:

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // A real SOL-quoted pump.fun curve read from mainnet (tests/fixtures/curve_sol_active.b64).
    let data = base64(include_str!("../tests/fixtures/curve_sol_active.b64"))?;
    let curve = BondingCurve::decode(&data)?;
    let (vt, vs) = (curve.virtual_token_reserves as u128, curve.virtual_sol_reserves as u128);
    println!("virtual reserves: {vt} token units, {vs} lamports");
    println!("k = x * y = {}", vt * vs);

    let fees = Fees::new(95, 30); // 0.95% protocol + 0.30% creator
    let (p, c) = (95, 30);

    let budget = 1_000_000_000; // 1 SOL
    let by_hand = buy_with_sol(vt, vs, budget, p, c);
    let by_crate = curve.buy_exact_sol_in(budget as u64, fees)?.tokens_out as u128;
    println!("buy with 1 SOL:      by hand {by_hand} tokens, crate {by_crate}");
    assert_eq!(by_hand, by_crate);

    let tokens = 10_000_000_000_000; // 10 million tokens (6 decimals)
    let by_hand = buy_exact_tokens(vt, vs, tokens, p, c);
    let by_crate = curve.buy_exact_tokens_out(tokens as u64, fees)?.total_sol as u128;
    println!("buy 10M tokens:      by hand {by_hand} lamports, crate {by_crate}");
    assert_eq!(by_hand, by_crate);

    let by_hand = sell(vt, vs, tokens, p, c);
    let by_crate = curve.sell_exact_tokens_in(tokens as u64, fees)?.sol_out as u128;
    println!("sell 10M tokens:     by hand {by_hand} lamports, crate {by_crate}");
    assert_eq!(by_hand, by_crate);

    println!("all three match to the lamport");
    Ok(())
}

Note that k is slightly above 30 × 1,073,000,000 × 1015: every rounded-down trade leaves a sliver in the curve's favour, so k creeps up over the curve's life. A float version of the formula drifts by a few lamports for the same reason, which is enough to fail a tight slippage check.

Use the crate instead

pump-curve-rs does all of this with checked arithmetic, decodes every account layout pump.fun has written, derives the curve address from the mint offline, and adds slippage limits for the buy and sell instructions. No dependencies, no_std, no unsafe.

cargo add --git https://github.com/blixvip/pump-curve-rs

Limits to know: mayhem-mode coins use different parameters and are not modelled; curves quoted in a token other than SOL decode but are not priced in SOL; and the crate does not fetch anything, so you bring the account bytes from your own RPC.
